Лабораторна робота №4 — Узагальнений репозиторій
1. Реалізація
* IdentityExtractor<T> — функціональний інтерфейс для отримання унікального ідентифікатора об’єкта. Реалізується за допомогою лямбда-виразів або method reference під час створення репозиторію.
* GenericRepository<T> — узагальнений репозиторій, який зберігає об’єкти в LinkedHashMap<String, T>. Пошук за ключем у середньому має складність O(1). LinkedHashMap також зберігає порядок додавання елементів.
* findAll() повертає незмінну копію списку, тому зовнішній код не може змінити внутрішню структуру репозиторію.
* add() додає об’єкт або кидає DuplicateIdentityException, якщо його ідентифікатор уже існує.
* addIfAbsent() додає об’єкт лише за відсутності дубліката та повертає false, якщо такий ідентифікатор уже існує.
* Логування операцій виконується в GenericRepository за допомогою SLF4J і Logback. Використовуються рівні INFO, WARN та ERROR.
2. Перевірені типи
Тип	Вид	Identity extractor
EquipmentItem	Змінюваний клас	EquipmentItem::getInventoryNumber
SportsCustomer	Record	SportsCustomer::passportNumber
ReturnInspection	Record	ReturnInspection::inspectionId
RentalAgreement	Record	Паспорт клієнта + інвентарний номер обладнання + дата початку оренди
EquipmentItem має змінювані поля pricePerDay і condition, але його ідентифікатор inventoryNumber оголошений як final. Тому ідентичність об’єкта не змінюється після додавання до репозиторію.
Сутності, record-и та enum-и з попередніх лабораторних робіт не переписувалися. GenericRepository не вимагає спільного базового класу або інтерфейсу для об’єктів, які зберігаються.
3. Завантаження даних із CSV
Файл data/equipment.csv містить коректні та некоректні записи, зокрема повторний запис з ідентифікатором SKI-001.
Під час завантаження даних EquipmentLoader перевіряє записи та пропускає некоректні рядки. Після цього об’єкти додаються до репозиторію. Дублікат SKI-001 відхиляється, що демонструє перевірку унікальності ідентифікаторів на реальних даних CSV.
4. Тестування
Тести JUnit 5 розміщені у файлі:
src/test/java/ua/rental/repository/GenericRepositoryTest.java
Перевіряються:
* додавання та пошук об’єктів;
* повернення Optional.empty() для відсутнього елемента;
* виникнення DuplicateIdentityException під час додавання дубліката;
* поведінка addIfAbsent() та незмінність розміру репозиторію;
* видалення наявних і відсутніх елементів;
* незмінність списку, який повертає findAll();
* робота узагальненого репозиторію з різними типами;
* перевірка некоректних елементів.
Для запуску тестів використовується команда:
./gradlew test
Результат тестування: 16 тестів успішно пройшли.
5. Порівняння Map і List
Для порівняння ефективності пошуку реалізовано окремий клас SearchBenchmark.
Benchmark створює 100 000 об’єктів EquipmentItem і порівнює два способи пошуку:
* пошук за ідентифікатором через GenericRepository (Map);
* послідовний пошук у List.
Перед вимірюваннями один раз створюється snapshot списку за допомогою findAll(). Також виконується прогрівання перед вимірюваннями.
Проводиться 7 повторних вимірювань для кожного сценарію. Для оцінки продуктивності обчислюються медіана та мінімальний час виконання.
Запуск benchmark
./gradlew searchBenchmark
Або запуск класу ua.rental.repository.SearchBenchmark безпосередньо через IDE.
Конфігурація
* Кількість об’єктів: 100 000.
* Кількість циклів прогрівання: 3.
* Кількість повторних вимірювань: 7.
* Одиниця вимірювання: наносекунди (ns).
* Метрики: медіана та мінімальний час виконання.
Результати вимірювань
Сценарій пошуку	Map, медіана (нс)	Map, мінімум (нс)	List, медіана (нс)	List, мінімум (нс)
Перший елемент	333	291	375	333
Останній елемент	292	291	2 906 541	2 673 333
Відсутній елемент	291	250	2 874 958	2 519 917
Висновки
Результати benchmark демонструють, що пошук через Map значно швидший за лінійний пошук у List для останнього та відсутнього елементів. Map забезпечує очікувану середню складність пошуку O(1), тоді як лінійний пошук має складність O(n), оскільки може потребувати перегляду всіх елементів. Отже, використання GenericRepository є ефективнішим для пошуку об’єктів за ідентифікатором у великих колекціях.
